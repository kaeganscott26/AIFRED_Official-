# No-Drift Contract

This document prevents `AIFRED_Official-` from becoming another patched prototype.

## The Rule

Do not drift.

Every feature, file, module, prompt, test, UI element, backend route, and report must serve the flagship product definition.

AIFRED is an interpretation layer for music production.

It does not exist to be a generic AI chatbot, fake analyzer, or magic mix button.

## Flagship Identity

AIFRED helps producers understand what their tools are doing, measure their progress, and build confidence through verified signal analysis and contextual interpretation.

Processing changes the sound.

AIFRED changes the producer.

## Build Identity

Current AIFRED = proof prototype / last-known-good reference.

`AIFRED_Official-` = clean flagship rebuild.

Old repos are reference material only.

The flagship does not inherit old confusion.

## Non-Negotiables

- no fake meters
- no placeholder values shown as real analysis
- no hardcoded secrets
- no hardcoded personal paths
- no stale state presented as live data
- no generic metric dumping
- no canned advice engine
- no hidden reference-pool leakage
- no mega-prompts
- no skipping acceptance gates
- no CI/CD until intentionally enabled
- no copying old code without inspection
- no building GUI before the truth layer is defined

## Layer Responsibilities

Python tells the truth.

AI explains the truth.

GUI reveals the truth.

Reports preserve the truth.

Backend supports the platform.

Admin controls operations.

Website presents the product.

If a layer tries to do another layer’s job, stop and review.

## Source of Truth

Every response, report, and UI state must trace back to one or more of:

- measured signal
- active mode
- user question
- selected reference/target
- comparison file
- export history
- saved report
- general engineering knowledge

No mysterious “AI said so.”

## Acceptance Philosophy

A feature is not done when it appears on screen.

A feature is done when it:

1. is connected to verified data
2. handles unavailable data honestly
3. passes the active mode contract
4. avoids irrelevant output
5. fails gracefully
6. is documented
7. does not create drift

## Stop Conditions

Stop work immediately if:

- a task requires guessing architecture
- a prompt asks an agent to build too many systems at once
- a feature requires fake data
- a config requires a secret in source
- old repo behavior conflicts with this contract
- a change would make the product less trustworthy
- the user has not approved moving to the next phase

## Final Standard

AIFRED is not ready for paid release until there are zero known release-blocking bugs, zero fake behavior, and zero trust-breaking defects.
