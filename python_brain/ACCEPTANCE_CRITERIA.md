# Python Truth Layer Acceptance Criteria

## Current Phase Gate

This phase passes when the module contracts, data model contract, stub interfaces, skipped test skeletons, fixture rules, and script rules exist without production implementation.

## Future Implementation Gate

The Python Truth Layer is not accepted until it can:

- Load approved audio inputs without leaking private paths.
- Calculate sample peak, RMS, headroom, and clipping state.
- Calculate loudness and loudness range using approved math.
- Calculate crest factor, dynamics, and transient evidence.
- Calculate stereo/correlation and mid/side evidence.
- Calculate frequency-band and tonal-balance evidence.
- Preserve Analyze Mode isolation.
- Preserve Reference Mode target-only comparison.
- Preserve Compare Mode A/B-only behavior.
- Select relevant metrics from user question, mode, and source state.
- Create explicit source-of-truth and confidence labels.
- Produce factual interpretation packets for AI without final advice.
- Write `.txt` and `.html` reports that preserve facts and context.
- Handle unavailable, stale, invalid, or incomplete data honestly.

## Release-Blocking Failures

- Any fake metric output.
- Any final advice generated by Python.
- Any hidden reference-pool use in Analyze or Compare Mode.
- Any hardcoded local path or secret.
- Any test that passes by asserting placeholder behavior as complete.
- Any report that omits source-of-truth state.
