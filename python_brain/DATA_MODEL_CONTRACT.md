# Python Truth Layer Data Model Contract

## Purpose

This contract defines the data shape expectations before implementation.

The Python Truth Layer must pass facts and state between modules without implying unavailable data is valid.

## Required Concepts

### Audio Input

Must eventually include:

- sample data or approved audio handle
- sample rate
- channel count
- duration
- source label
- safe display name
- limitations

Must not include private absolute paths in user-facing output.

### Metric Result

Must eventually include:

- metric name
- value
- unit
- availability state
- confidence state where relevant
- calculation window or duration
- limitations
- factual flags

Unavailable is not zero.

Zero is not unavailable.

Stale is not live.

### Analysis State

Must eventually include:

- active mode
- source-of-truth label
- confidence state
- freshness/staleness state
- analysis window
- limitations
- relevant metrics
- factual flags

### Interpretation Packet

Must eventually include:

- user question
- active mode
- source-of-truth label
- confidence state
- selected relevant facts
- compare/reference context only when allowed
- limitations

It must not include final advice generated by Python.

### Report Draft

Must eventually include:

- product/version
- timestamp
- session/track label if available
- active mode
- user question
- source-of-truth label
- confidence state
- relevant metrics
- factual flags
- limitations
- save target

Reports may be human-readable, but they must preserve facts and context rather than inventing advice.
